# 双机无缝迁移指南（项目 + AI 对话记录）

场景：把 MyTime 项目**连同 ZCode 的记忆与全部对话记录**搬到另一台电脑工作，之后再搬回来。
两条硬规则：**代码靠 git 往返**；**git 装不下的东西靠导出包私有通道往返**。

## 方案选择

- **只迁 MyTime**：用本目录的 `migrate-export/import` 脚本（见下文四步）
- **整个 `E:\study\zi` 文件夹连其他项目一起迁**：见文末「整文件夹迁移」——整拷自带各项目
  的 gitignored 私密文件（MyTime 的 .ssh-key、deploy/config 等自动包含），
  需要单独走的只有 `C:\Users\Administrator` 下的 ZCode 会话库/记忆与 `~/.ssh`

## 一图看懂搬什么

| 内容 | 载体 | 怎么走 |
|---|---|---|
| 项目代码与全部标签 | git | `push` / `pull`（GitHub） |
| git 装不下的：部署私钥、deploy/config、本地 server 数据 | 导出包 `secrets/`、`server-data/` | U 盘/加密网盘（**绝不入库**） |
| AI 记忆（每会话自动加载） | `~/.zcode/cli/memories/projects/mytime-*` | 导出包 |
| 全部对话记录 | `~/.zcode/cli/db/db.sqlite*` | 导出包 |
| VPS 上的线上数据 | 不用迁 | 本来就在服务器上，两台电脑共用 |

## 第 1 步：离开这台电脑前

```bash
# 1. 代码全部上云（工作树必须干净——有半成品就先 commit，哪怕是 WIP）
git add -A && git commit -m "wip: 迁移前快照" && git push

# 2. 打包 git 装不下的部分（默认输出到仓库上级目录，64MB 左右）
node scripts/migrate-export.mjs
```

把输出的 `mytime-migrate-export/` 整个拷到 U 盘/加密网盘，**到新机后删除中转副本**（里面有私钥和对话记录）。

## 第 2 步：新电脑到达后

```bash
# 0. 前置：装 Node 22+ 与 Git（打包 APK 才需要 Android Studio）
# 1. 克隆项目到任意目录，进入项目根目录
git clone https://github.com/Modify6/MyTime.git
cd MyTime

# 2. 一键恢复（私钥/配置/本地数据/记忆/对话记录，含 Windows ACL 收紧）
node scripts/migrate-import.mjs <U盘里的 mytime-migrate-export 目录>

# 3. 环境收尾（脚本末尾会打印同样的清单）
npm install && npm install --prefix server && npm install --prefix web
git config core.hooksPath .githooks
ssh mytime "echo ok"      # 验证服务器连通（用 Windows OpenSSH，见 deploy/README.md）
npm --prefix web test     # 39 例应全过
```

**记忆键的注意点**：ZCode 的记忆目录名（`mytime-<哈希>`）由项目路径派生。
- 新机把项目放在**同名路径**（如都在 `E:\study\zi\MyTime`）→ 自动匹配，无感
- 路径不同 → 打开一次 ZCode 后它会生成新键目录，把导出的 memory 文件夹内容拷进新键目录即可（导入脚本会提示）

**对话记录（和 ZCode 的对话无缝衔接）**：全部对话就在 `~/.zcode/cli/db/db.sqlite` 一个库里
（实测：9 个会话 / 3294 条消息 / 1.1 万个消息片段），随导出包走。衔接条件：

1. 新机安装**同版本 ZCode** 并**登录同一账号**（会话库是本地文件，账号只影响模型鉴权）
2. 导出/导入前后**都要关闭 ZCode**（库文件被运行中的 ZCode 占用，WAL 未合并会丢最近几句）
3. 打开新机 ZCode → 会话列表里出现全部历史会话 → 点开原对话直接继续，上下文完整
4. 项目放在**相同路径**（如都为 `E:\study\zi\MyTime`）——对话里引用的工具路径与记忆键才完全对得上
5. 双保险：就算 resume 出意外，AI 记忆（memories）会自动加载到任何新会话，加上仓库里的
   `docs/lessons.md` 与 CHANGELOG，新开对话说"继续 MyTime 项目"即可快速接上

## 第 3 步：在新电脑上日常工作

和平时完全一样——ZCode 自动加载记忆，对话接着聊；代码改动照常走 `release.mjs` 发版。

唯一纪律：**不要两台机器同时改代码**。离开任何一台前 `git push`，到达另一台先 `git pull`。

## 第 4 步：搬回原来的电脑

完全对称，但**先做「回迁的三个防覆盖动作」**（git 两边对齐 / 本机对话库备份 / 单主原则）：

```bash
# 新电脑上：
git add -A && git commit -m "wip: 回迁前快照" && git push
node scripts/migrate-export.mjs        # 打包这段时间新产生的记忆/对话

# 原电脑上：
git pull                                # 先对齐 git
node scripts/migrate-import.mjs <U盘里的导出目录>
```

导入脚本对已存在的会话库会**先备份再覆盖**（`~/.zcode/backup-migrate-时间戳/`），原电脑迁移前没同步进库的对话不会丢。

## 常见坑

- **ZCode 没关就导出/导入**：WAL 未合并/文件被锁。关掉重跑即可，脚本会检测并提示
- **忘了同步 `deploy/config`**：表现为 `ssh mytime` 正常但 `upload.sh` 报 SERVER_HOST 未设置——它是 gitignore 的，靠导出包走
- **VPS 不用搬**：线上数据/快照都在服务器上，两台电脑只是它的两个客户端
- **APK 打包工具链**（JDK/Android SDK）不随迁移走：新机需要打包时按 `apk.bat` 的提示装 Android Studio，或直接用 CI Release 的 APK

## 整文件夹迁移（整个 `E:\study\zi`，含其他项目）

适用：多项目整体搬家。**前提：新机使用完全相同的路径 `E:\study\zi`**（ZCode 记忆键由路径派生、
对话里引用的路径才能无缝对应）。实测现状：zi 文件夹约 28GB，其中可再生的 node_modules 散布各项目。

**第 1 步 · 走之前（旧机）**

```bash
# 1. 退出 ZCode（对话库要拷）
# 2. 各项目收尾：未推送的 commit push 掉（git 是另一层保险，非必须——整拷自带 .git）
# 3. robocopy 整拷（排除可再生成的依赖与构建产物，实际量级大幅缩小）
robocopy E:\study\zi <目标盘>:\study\zi /E /XD node_modules .gradle /XF MyTime.apk /R:1 /W:1 /MT:8
#    ⚠ auto-down-load(17G)、7bvxhz-baidu-buyer(8.8G) 等大目录按需加 /XD 排除
# 4. 拷 C 盘用户目录三样（连同子目录）：
#    ① C:\Users\<你>\.zcode\cli\db\            —— 全部对话记录
#    ② C:\Users\<你>\.zcode\cli\memories\      —— 全部项目 AI 记忆
#    ③ C:\Users\<你>\.ssh\                     —— 部署私钥副本与 mytime 主机别名
#    （可选）%LOCALAPPDATA%\MyTime\jdk 与 %LOCALAPPDATA%\Android\Sdk —— 本机打包 APK 才需要
```

**第 2 步 · 新机到达**

1. 装同版本 ZCode 并登录同一账号；装 Node 22+ 与 Git
2. 退出 ZCode，把上面三样放回**相同的用户目录路径**
3. 确认 zi 文件夹已就位 `E:\study\zi`（盘符路径必须一致）
4. 打开 ZCode：记忆自动加载、全部对话在会话列表里、直接接着聊
5. 各项目按需 `npm install`（node_modules 被排除了）；MyTime 专项验证：
   `git config core.hooksPath .githooks` → `ssh mytime "echo ok"` → `npm --prefix web test`
6. 要本机打包 APK：装 Android Studio 或还原便携工具链，并配好 `JAVA_HOME/ANDROID_HOME`

**第 3 步 · 回迁**：方向对调，但**先做三个防覆盖动作**（见下节「回迁的三个防覆盖动作」）。

## 回迁的三个防覆盖动作（首迁不需要，回迁必做）

回迁是"新机文件覆盖旧机文件"——分离期两边各自产生的数据会打架：

1. **git 先对齐（防代码覆盖丢失）**
   新机：全部 commit + push。
   本机：也 commit + push（分离期本机若有改动）→ `git pull` 对齐。
   两边 git 对齐后再 robocopy，git 目录内容一致，覆盖才无冲突。**绝不带着未提交改动直接被 robocopy 覆盖。**

2. **本机对话库先备份（防对话丢失）**
   回迁前把 `C:\Users\<你>\.zcode\cli\db\` 整个拷一份留底（如 `db-backup-日期/`）。
   分离期本机若也开过 ZCode 聊过别的，那些对话只存在于本机库里，被覆盖前先留底。

3. **单主原则（从源头避免冲突）**
   分离期**只在当前在用的那台机器上开 ZCode 对话**，另一台不开新会话——
   这样会话库单向覆盖零丢失。若两边都聊过：把对方机器聊出的重要结论沉淀进
   仓库文档（lessons/CHANGELOG）后再覆盖——对话的长期价值本来就该沉淀在 git 里。

**robocopy 增量特性**：回迁时它只复制有差异的文件，比首迁快得多；默认**不删除**目标端多余文件。

**为什么整拷后还需要那三样**：ZCode 的对话/记忆和 SSH 配置都在 `C:\Users\<你>` 用户目录，
不在 zi 文件夹里；而 zi 内的 MyTime 私密文件（.ssh-key、deploy/config）整拷自然包含，
这正是整文件夹方案比单项目脚本更省事的地方。
